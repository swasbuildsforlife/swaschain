# Contributing to SwasChain

## Development Approach

SwasChain is developed incrementally, with protocol design, implementation, and
testing kept closely aligned.

## Before Making Changes

1. Understand the relevant protocol component.
2. Keep changes focused and easy to review.
3. Update documentation when the protocol behavior changes.
4. Add tests when implementing executable protocol logic.

## Commit Guidelines

Use clear commit messages that describe the purpose of the change.

Examples:

- `docs: clarify transaction lifecycle`
- `feat: implement transaction validation`
- `test: add transaction validation tests`
- `refactor: simplify block validation`

## Development Principle

Protocol behavior should remain deterministic, understandable, and testable.
Changes should build on the existing protocol foundation rather than introducing
unnecessary complexity.
